# PIX2 and editor audit — 2.2.0 reference

**Purpose:** Single source for evaluating the external review, reproducing claims against this checkout, and recording what 2.2.0 changes or deliberately retains. Release documentation must link to this record and summarize only verified outcomes.

**Baseline:** `main`, NOIRADIX 2.1.8 / PIX2 1.1, commit `7649ab1` (2026-11-12).
**Working branch:** `main`, per the user's explicit instruction.
**Status:** 2.2.0 implementation and verification record; release state is tracked by Git tags and GitHub Releases.
**Scope:** Product claims, format behavior, code/docs consistency, Unity frame identity, maintenance notice, and architecture boundaries. No release tag or publication is part of this phase.

## Decisions before evaluating claims

- PIX2 is intentionally a human-readable text source format. We will not switch canonical serialization to compact runs merely to reduce tokens; `line`/`rect`/`fill` normalize to explicit pixels by design. PIX2 1.1 does not mandate that normalization, so preserving authored primitives can be evaluated later as an optional authoring mode without changing this canonical behavior.
- Studio's full-document snapshot history and the large app entry points are accepted trade-offs for the intended product scope unless measured evidence demonstrates a product-level failure. Do not refactor solely to lower line counts.
- Concrete defects and false claims must both be called out. A documented intention does not excuse incorrect UI behavior, data loss, misleading license claims, or stale docs.
- Distinguish current behavior from historical proposals and from external reviewer estimates. Token counts depend on model tokenizer; they are not universal constants.

## AI context and future MCP direction

- The existing full-project prompt mode intentionally includes the current serialized document. The context cost is a real trade-off, not a universal fixed token count.
- 2.2.0 adds an explicit **instructions only** choice that excludes project source, retains the existing **prompt + full PIX2 context** option, and adds a separate single-frame prompt/copy/import path.
- Users should select a model whose current provider-documented input window can hold the generated instructions plus chosen source, and whose output budget can return the requested complete document. Model names and limits are not hard-coded here because providers change them; large projects should use frame-scoped work or check the provider's current model documentation.
- **Future, not 2.2.0 functionality:** investigate a local-first MCP adapter that exposes bounded PIX2 operations (read a frame or selected line range, propose/apply a validated frame patch, inspect diffs) instead of requiring the model to ingest and rewrite a full project. Keep credentials/account services out of the editor; do not claim MCP support until transport, permissions, undo/recovery, offline behavior and security limits are specified and implemented.
